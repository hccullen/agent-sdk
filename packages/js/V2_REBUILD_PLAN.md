# V2 Rebuild Plan — Corti Agent SDK (TypeScript)

## Goal

Replace the v1 SDK (a thin wrapper around `@corti/sdk`) with a v2-only SDK
built from the ground up on the [openapi-ts](https://openapi-ts.dev/) toolchain:
`openapi-typescript` for type generation + `openapi-fetch` for the runtime
HTTP client. Zero dependency on `@corti/sdk`.

## Architecture

### Layer 0 — Generated types (done)

`src/gen/api-v2.d.ts` — auto-generated by `openapi-typescript`. Provides:
- `paths` — all REST endpoints with full type inference
- `components.schemas` — every request/response schema
- `operations` — per-operation type bundles

Regenerate with: `npm run generate`

### Layer 1 — HTTP client (openapi-fetch)

`src/client.ts` — `CortiClient`

The single entry point. Wraps `createClient<paths>()` from openapi-fetch with:
- Base URL resolution (region: `eu` / `us`, or custom)
- Bearer token auth (`Authorization: Bearer <token>`)
- Tenant header (`Tenant-Name: <tenant>`)
- A2A version header (`A2A-Version: 1.0`) on A2A endpoints
- Configurable `fetch` override (for testing / custom transports)
- Middleware support (logging, retry, etc.)

```ts
class CortiClient {
  // The raw openapi-fetch client for direct API access
  readonly raw: ReturnType<typeof createClient<paths>>;

  // High-level resource clients
  readonly agents: AgentsResource;
  readonly contexts: ContextsResource;
  readonly registry: RegistryResource;
  readonly models: ModelsResource;

  constructor(opts: {
    token: string;           // Bearer token
    tenant: string;          // Tenant-Name header
    region?: "eu" | "us";    // default: "eu"
    baseUrl?: string;        // override region entirely
    fetch?: typeof fetch;    // custom fetch (testing)
  });
}
```

## Key design decisions

### 1. No `@corti/sdk` dependency

The v2 SDK is self-contained. Auth is a bearer token + tenant header passed
to the `CortiClient` constructor. The generated `openapi-fetch` client handles
all HTTP. This removes:
- The peer dependency on `@corti/sdk`
- The fragile `getCardUrl()` / `getAuthHeaders()` coupling
- The `_options` private field access hack
- The monkey-patch on `client.agents.create`

### 2. REST-first A2A

The v2 SDK uses the **HTTP+JSON binding** (`message:send`, `message:stream`)
as the primary conversational surface, not the JSON-RPC binding. This is
simpler (no JSON-RPC envelope construction/unwrap), type-safe via openapi-fetch,
and directly matches the spec's `A2ASendMessageRequest` / `A2ASendMessageResponse`
schemas.

The JSON-RPC binding (`POST /agents/{id}/a2a`) remains available via
`client.raw.POST("/v2/agentic/agents/{agentId}/a2a", ...)` for advanced users.

### 3. SSE streaming via the REST binding

`POST /agents/{id}/a2a/message:stream` returns `text/event-stream`. The SSE
parser from the current `rpcTransport.ts` (which is spec-compliant) is reused
in `streaming.ts`. Each SSE event's `data` is JSON-parsed into an
`A2AStreamResponse` (exactly one of `task`, `msg`, `statusUpdate`,
`artifactUpdate`).

### 4. Connector factories

```ts
export const connectors = {
  registry: (name: string, opts?: { config?: Record<string, unknown> }) => ({
    type: "registry" as const, name, ...opts
  }),
  mcp: (opts: { name: string; url: string; auth?: ConnectorAuth }) => ({
    type: "mcp" as const, ...opts
  }),
  agent: (agentId: string) => ({
    type: "agent" as const, agentId
  }),
  a2a: (url: string, opts?: { name?: string }) => ({
    type: "a2a" as const, url, ...opts
  }),
  schema: (opts: { name: string; schema: object; description?: string; transition?: "complete" | "input_required" }) => ({
    type: "schema" as const, ...opts
  }),
};
```

### 5. Credentials

v2 connector auth is configured on the connector itself (`CommonConnectorAuth`),
not forwarded as DataParts at call time (that was a v1 pattern). The `CredentialStore`
type and the proactive auth-part injection in `AgentContext` are dropped.

If runtime credentials are needed, they go in the `A2ASendMessageRequest.metadata`
field or the connector's `auth.ref` field (server-side stored secret reference).

### 6. Pagination

List endpoints return `{ ..., nextPageOffset: number | null, totalSize?: number }`.
The SDK provides a `paginate()` helper:

```ts
for await (const page of client.agents.list({ pageSize: 50 })) {
  // page.agents
}
```

### 7. JSON Merge Patch

`PATCH /agents/{id}` uses `application/merge-patch+json` (RFC 7386).
openapi-fetch handles this transparently — just pass the partial body.
The SDK's `AgentHandle.update()` maps directly to `client.PATCH()`.

## v1 → v2 API mapping

| v1 concept | v2 equivalent |
|---|---|
| `CortiClient` from `@corti/sdk` | `CortiClient` (new, self-contained) |
| `client.agents.create()` | `client.agents.create()` (REST POST) |
| `client.agents.get()` | `client.agents.get()` (REST GET) |
| `client.agents.list()` | `client.agents.list()` (REST GET) |
| `client.agents.update()` | `client.agents.update()` (REST PATCH, merge-patch) |
| `client.agents.delete()` | `client.agents.delete()` (REST DELETE) |
| `getCardUrl(agentId)` → JSON-RPC URL | `POST /agents/{id}/a2a/message:send` (REST) |
| `rpcCall()` → JSON-RPC `message/send` | `POST /agents/{id}/a2a/message:send` (REST) |
| `rpcStream()` → JSON-RPC `message/stream` | `POST /agents/{id}/a2a/message:stream` (REST SSE) |
| `experts` + `mcpServers` | `connectors` (unified array) |
| `ephemeral` boolean | `lifecycle: "ephemeral" \| "persistent"` |
| `authType` / `token` on MCP | `auth: { type, scope, redirectUrl, ref }` |
| `CredentialStore` + auth DataParts | Dropped — auth lives on the connector |
| `Corti.AgentsTask` | `components["schemas"]["CommonTaskResponse"]` |
| `Corti.AgentsMessage` | `components["schemas"]["CommonMessage"]` |
| `Corti.AgentsPart` | `components["schemas"]["CommonPart"]` |
| `kind: "task"` / `kind: "message"` | Dropped — v2 uses REST, not kind-tagged JSON-RPC |
| `StreamEvent` with `kind` normalisation | `A2AStreamResponse` (already has `task`/`msg`/`statusUpdate`/`artifactUpdate`) |

## Open questions

1. **Token refresh** — v2 uses a static bearer token. Should the SDK support
   a token provider function `() => Promise<string>` for OAuth token refresh?
   (Recommended: yes, as an optional constructor param.)

2. **JSON-RPC surface** — Should we expose a typed wrapper for the JSON-RPC
   binding (`POST /agents/{id}/a2a`), or leave it as raw `client.raw.POST()`?
   (Recommendation: raw for now; add a wrapper if users ask.)

3. **Schema connector** — The `schema` connector type is new in v2. It allows
   defining a JSON Schema tool that the LLM calls to submit structured output.
   The SDK should expose this via `connectors.schema()`.

4. **Pagination helper** — Should `list()` return a flat async generator or
   a page-based API? (Recommendation: page-based with an optional `paginate()`
   async generator helper.)
